# Review Checklist

## 1. PR 合并前

| 检查项 | 必须满足 |
| --- | --- |
| 范围 | PR 只解决一个明确任务 |
| 文档 | 接口、数据结构、部署或范围变化已同步文档 |
| 验证 | PR 描述包含本地验证方式和结果 |
| 安全 | 未提交 `.env`、API Key、Token、完整密钥日志 |
| 接口 | 返回结构符合 `API_CONTRACT.md` |
| 数据 | 字段命名和证据链符合 `DATA_MODEL.md` |
| UI | 页面有加载、失败、空状态 |
| 缓存 | 使用缓存时前端明确标注 |

## 2. 模块自测

### 前端

- 首页能说明项目用途。
- 主流程页面能展示任务步骤。
- 数据、文献、图谱页面能处理空数据和失败响应。
- 图谱节点详情不溢出、不遮挡核心信息。

### 后端

- `/api/v1/health` 可用。
- 创建任务、查询任务、获取结果接口可用。
- 错误响应包含 `code`、`message`、`request_id`。
- Qwen 调用有超时、重试或降级策略。

### 数据

- 原始来源、清洗结果、字段字典可复现。
- 关键字段单位明确。
- 缺失率和质量评分可计算。
- CSV 导出可被常见表格工具打开。

### 文献与图谱

- 文献总结结构固定。
- 核心结论绑定来源。
- 图谱边绑定 `evidence_ids`。
- 无证据内容不作为最终结论展示。

## 3. 演示前

| 检查项 | 必须满足 |
| --- | --- |
| 公网访问 | 首页、任务页、数据页、文献页、图谱页可打开 |
| 主案例 | 固定输入可完整跑通 |
| 缓存兜底 | 外部服务失败时仍能展示真实运行缓存 |
| 导出 | CSV、数据字典、溯源报告可下载 |
| 截图 | 页面无明显错位、报错、占位文案 |
| 口径 | 演示话术不超过已实现能力 |

## 4. 文档审查

- README 是否能作为唯一入口。
- PRD 是否仍然只承诺 MVP 范围。
- DESIGN 是否与实际架构一致。
- API_CONTRACT 是否与后端接口一致。
- DATA_MODEL 是否与数据库和前端类型一致。
- ACCEPTANCE 是否能覆盖当前演示目标。
