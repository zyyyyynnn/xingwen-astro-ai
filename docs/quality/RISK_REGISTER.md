# Risk Register

## 高风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 外部数据源不稳定 | Demo 中断、数据无法刷新 | 真实运行缓存兜底，展示 cached 标识 |
| 模型输出编造或格式不稳定 | 文献总结和图谱可信度下降 | JSON Schema 校验，结论绑定来源 |
| API Key 泄露 | 账号和费用风险 | 只放后端环境变量或部署 Secrets，日志脱敏 |
| 三大功能割裂 | 作品像功能拼盘，竞争力下降 | 所有页面围绕同一 ResearchTask 和 Evidence 链 |
| 主案例范围扩散 | 进度失控 | MVP 固定 `exoplanet_host_star` |

## 中风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 前后端字段不一致 | 联调成本上升 | `API_CONTRACT.md` 和 `DATA_MODEL.md` 先行 |
| 图谱只好看但无证据 | 评审质疑科研价值 | 每条边必须有 `evidence_ids` |
| 文献总结缺少引用脉络 | 难以体现科研工具价值 | PaperSummary 绑定 paper/source/evidence |
| 部署平台限制 | 公网 Demo 不稳定 | 前端、后端、数据库分离部署，保留缓存模式 |
| 成员任务边界不清 | 重复开发或遗漏 | 按 `MODULES.md` 和 `BACKLOG.md` 认领 |

## 低风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| UI 细节不统一 | 展示专业度下降 | DESIGN 和前端组件规范后续补齐 |
| 导出格式不够美观 | 材料复用成本增加 | 先保证 CSV/JSON 正确，再补报告模板 |
| 文档过期 | 新成员误解项目 | PR 改接口/模型/范围时必须同步文档 |

## 风险处理原则

1. 影响 Demo 稳定性的风险优先处理。
2. 影响科研可信性的风险优先处理。
3. 影响美观但不影响主链路的风险后置。
4. 无法本周解决的风险必须写明兜底方案。
