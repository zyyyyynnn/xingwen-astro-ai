## 这份资料解决什么问题

AutoAstro 是基于 LLM 的天文数据分析自动化框架，用户输入研究目标、数据集和元信息，系统自动完成全链路分析并输出报告与可视化。来自贵州大学公共大数据国家重点实验室，论文发表于 2026 年。

## 我们项目的哪个模块要用它

对应 `services/data_pipeline`（C 岗位-夏铭灿）。核心复用点：数据交叉匹配逻辑、LLM 驱动的任务推荐与分解、分析代码自动配置与执行、评测指标体系。

## 架构概要

三阶段工作流：Stage 1 Task Recommendation 解析用户目标，基于历史记录推荐任务方案；Stage 2 Task Execution 执行数据交叉匹配→框架选择→任务推荐→代码配置→分析与可视化；Stage 3 Task Decomposition 将复杂任务递归分解为子任务，带错误检测与纠正机制。

覆盖三类分析域：可视化分析（HR 图、Hubble 关系、银道面分布、天体分类）、统计分析（异常红移、光度-星等关系、流量-红移相关性）、时序分析（DSG 分类、多波段流量预测、恒星流量预测）。

## 核心代码接口

12 个 .py 文件位于 `code/` 目录：

- `framework_executor.py` (32KB): 主执行器，编排全流程
- `prompt.py` (27KB): 所有 LLM Prompt 模板
- `load_and_analyze_data.py` (27KB): 数据加载与分析
- `analyze.py` (15KB): 分析逻辑
- `cross_match.py` (14KB): 数据交叉匹配
- `tools.py` (13KB): 工具集封装
- `llm_api.py` (8.4KB): LLM API 调用层
- `error_correction.py` (6.6KB): 错误纠正
- `plan_generate.py` (2.2KB): 计划生成
- `code_executor.py` (1.9KB): 代码执行器
- `token_human.py` (1.1KB): Token 人类反馈
- `task_memory.py` (129B): 任务记忆

## 评测基准（NL2Astro）

17 个数据集，48 条指令，覆盖参数预测、模型构建、理论验证、表格/数据/图像/时序。通过率 91%，效率超人类专家 6.69%（平均 8.32 分钟 vs 82.67 分钟）。Base LLM 对比：DeepSeek V3 (86% PR) > Qwen-Max > GPT-4o。

评测指标：Aggregate Score (AS)、Field Coverage Rate (FCR)、Redundant Field Rate (RFR)、Time/Token Cost (TiC/ToC)、Pass Rate (PR)。

## Qwen 迁移要点

`llm_api.py` 中调用 DeepSeek 的部分，迁移到 Qwen 只需要改三行：`api_key` 改为 `os.getenv("DASHSCOPE_API_KEY")`，`base_url` 改为 `https://dashscope.aliyuncs.com/compatible-mode/v1`，`model` 从 `deepseek-chat` 改为 `qwen-plus` 或 `qwen-max`。OpenAI 兼容模式，prompt、function calling、流式输出代码不用改。

## 注意事项

代码使用 mmpretrain 框架（VGG/ResNet/SwinTransformer 等），需要 GPU 推理，M1 阶段不引入。本地客户端（Windows）+ 服务端（Linux）分离部署模式。代码中的 ModelScope 存储空间配置需要单独处理。AutoAstro 评测中 Qwen-Max 倾向构建复杂神经网络架构，迁移时需评估 Qwen-Plus 在工具调用场景的稳定性。
