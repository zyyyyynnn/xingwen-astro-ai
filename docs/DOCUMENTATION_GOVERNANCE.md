# Documentation Governance

| 元数据     | 值                                      |
| ---------- | --------------------------------------- |
| Status     | Accepted                                |
| Authority  | 文档分类、唯一事实来源规则与文档门禁    |
| Applies to | 仓库内全部 Markdown、生成文档与参考资料 |

本文定义文档体系的组织规则。具体产品、架构或工程事实由对应专项文档维护；本文不重复这些事实。

## 1. 文档分类与权威顺序

文档按职责分为五类：

| 类别       | 位置                                                                                                                        | 职责                                     |
| ---------- | --------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------- |
| 入口       | `README.md`、`docs/README.md`                                                                                               | 项目定位、快速启动、文档地图             |
| 规范       | `PRD.md`、`DESIGN.md`、`SECURITY.md`、`docs/architecture/`、`docs/ai/`、`docs/design/`                                      | 产品范围、系统不变量、接口、数据、工作流 |
| 工程与交付 | `CONTRIBUTING.md`、`DEPLOYMENT.md`、`docs/setup.md`、`docs/engineering/`、`docs/product/`、`docs/quality/`、`docs/handoff/` | 实现、测试、协作、交付与运维规则         |
| 包级       | `packages/*/README.md`、`services/*/README.md`                                                                              | 单个包的使用方式与局部边界               |
| 参考与归档 | `docs/references/`、`docs/archive/`                                                                                         | 非规范参考与历史记录                     |

权威性冲突时按以下顺序处理：当前 Issue / PR 已批准范围 → 规范 → 工程与交付 → 入口 → 参考与归档。发现冲突时修正低权威来源，或通过 ADR / Issue 修改高权威事实，不自行选择“看起来更新”的版本。

职责边界：

- 入口文档不维护实现进度、完整技术栈、状态机或验收清单。
- 任何文档不维护“当前停在哪一步、下一步做什么”的进度叙述；实时状态由 GitHub Issues、Milestone、PR 与运行证据表达。
- 叙述性文本不以版本号标注接口、Schema 或数据模型分代；使用语义命名（如 Phase 0、Core）。版本化工件的文件名、变更历史与 ADR 除外。
- 包级 README 只说明该包的使用方式和边界，不重复全局架构。
- 参考资料不定义当前实现；归档资料不作为实现依据。

## 2. 唯一事实来源

同一事实只能有一个完整正文来源。其他文档可以：

- 用一至三句话摘要；
- 链接唯一正文；
- 说明该事实如何影响本文件范围。

其他文档不得：

- 复制完整枚举、状态机、技术栈表或验收清单；
- 维护同一流程的第二套步骤；
- 用不同术语重新描述同一领域对象；
- 把历史实现写成目标架构，或把目标架构写成已实现。

主要事实来源见 [docs/README.md](README.md)。

## 3. 标准元数据

规范性文档在标题后使用简短元数据表。字段分三类：

必填字段：

- `Status`
- `Authority`

允许但不强制的稳定字段，只描述稳定范围、来源或替代关系：

- `Scope`
- `Issue`
- `Superseded by`
- `Authoring source`
- `Time range`
- `Applies to`

禁止的进度字段，实时状态改由 Issue、Roadmap、Backlog 与运行证据表达：

- `Implementation`
- `Current runtime`
- `Target runtime`
- `Current model`
- `Target model`
- `Current`
- `Pending`
- `Progress`

字段规则：

- 前导元数据表只允许上述必填与稳定字段；出现任何其他键名一律失败，不静默忽略。
- 规范、参考与归档文档必须同时包含 `Status` 与 `Authority`。
- `Status` 取值：`Proposed`（尚待确认，仅供讨论）、`Accepted`（已确认，可驱动 Issue 与实现）、`Superseded`（已被新决策取代，仅保留历史与迁移解释）、`Archived`（不再维护，不作为实现依据）、`Reference`（外部或辅助资料，仅供研究和比较）。
- `Status` 描述文档决策状态，不描述代码完成状态；代码完成状态由 Issue、PR 与运行证据表达。
- `Authority` 在全部非 Reference / Archived 文档中唯一。
- `docs/archive/` 下的文档必须使用 `Status: Archived`；`docs/references/` 下的文档必须使用 `Status: Reference`。
- 禁止的是元数据字段名，不是合法正文术语或版本化工件内容。
- 状态变化必须在 PR 中说明替代关系。

`scripts/check-docs.mjs` 校验必填字段是否存在、拒绝白名单外字段与禁止字段，并按目录强制 `Status`。

## 4. 保留、合并、归档与删除

### 应合并

- 两份文档的受众、更新触发和主要事实相同；
- 一份文档超过一半内容只是另一份的摘要；
- 两份文档需要在同一次变更中始终同步。

### 应拆分

- 单份文档同时服务不同受众，且更新频率明显不同；
- 规范正文与操作手册混在一起；
- 文件过长导致局部修改难以审查，且拆分后仍能保持明确索引。

### 应归档

- 只描述历史阶段、旧口径或已被替代的决策，但仍有历史证据价值；
- 已被 ADR 或新规范取代。

归档文件放入 `docs/archive/`，注明时间范围和替代文档。

### 应删除

- 没有独有且仍有效的事实；
- 有效事实已迁移到唯一事实来源；
- 全部引用已同步；
- 删除不会破坏测试、生成流程或历史兼容说明。

一次性验证产物和临时报告不作为长期规范维护；生成文件不得手工重写；版本化 Prompt 是不可变工件，不做语言润色或内容合并。

## 5. 命名、链接与索引

- 文件名使用稳定、可预测的英文大写主题名或目录级 `README.md`。
- 不在标题或正文中写“最终版”“最新版”等会失效的词。
- 相对链接优先；链接文本说明目标文档职责。
- `docs/README.md` 是完整索引；根 README 不复制完整索引。
- 参考资料和生成物不进入规范文档索引表，除非明确标记类型。
- 文档移动或删除必须在同一 PR 更新全部链接。

## 6. 编写质量要求

- 开头说明 Authority、适用范围和不负责的内容；
- 使用统一领域术语，不创造展示同义词替代契约字段；
- 规则可验证，避免“合理”“完善”“尽量”“全面”等无验收含义表述；
- 一段只表达一个判断；删除宣传性与重复性文字；
- 示例与规范明确区分，示例不得扩展产品承诺；
- 枚举和状态只在唯一事实源完整定义；
- 当前事实、目标规范、历史记录和参考资料明确区分；
- 不写个人电脑路径、临时分支和已关闭任务流水账；
- 不包含密钥、私有 token、受限全文或模型私有推理。

## 7. 文档门禁

文档 PR 至少执行：

- `git diff --check`；
- `python scripts/check_foundation.py`：校验必需文件存在；
- `pnpm check:docs`：自动检查标题结构、代码块闭合、表格列数、Status 枚举、相对链接存在性、Mermaid 语法、关键元数据、Authority 唯一性、索引覆盖，以及 `docs/archive/`、`docs/references/` 的状态一致性；
- `node scripts/check-versionless-api.mjs`：拦截版本前缀 API 路径字面量。

人工审查项（无自动化门禁）：唯一事实源无新增语义冲突；无进度叙述与版本号口径；章节锚点引用未断裂。具体 PR 审查项见 [Review Checklist](quality/REVIEW_CHECKLIST.md)。
