# Architecture Decisions

## ADR-001：MVP 主案例固定为系外行星

为了保证国赛级 MVP 的稳定性和可复现性，第一阶段固定围绕“系外行星候选体与宿主恒星参数整合”推进。

## ADR-002：三大功能串成一条科研工作流

自动化数据分析、智能文献总结、学术图谱可视化不做三个孤立页面，而是围绕同一个科研任务串联。

## ADR-003：模型调用统一走后端

所有 Qwen 调用必须经过后端封装，前端不直接接触 API Key。

## ADR-004：模块间统一 JSON

数据分析、文献总结、图谱构建都必须输出结构化 JSON，方便前端展示和材料复用。

## ADR-005：公网 Demo 必须有缓存兜底

外部数据源和模型调用存在不稳定性。公网 Demo 必须能在实时调用失败时展示最近一次真实运行结果。
