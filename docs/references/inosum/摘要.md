本文是 [参考资料](../README.md) 目录下对第三方资料的项目内摘要。研究结论、指标和实现细节必须回到原始来源与代码核验。

## 1. 研究主题

InnoSum-Bench 是学术摘要质量评估框架，从 Factual Consistency (FC) 和 Cognitive Coverage (CC) 两个维度评估 AI 生成的论文摘要质量。同时提供了论文结构化解析代码，可将 Markdown 格式论文自动拆分为 7 类章节并提取摘要。

## 2. 资料结构

选定代码位于 `code/`。其中 `paper_summary.py` 展示以下流水线：论文 Markdown 清洗 → 按标题拆分章节 → 章节分类 → 各章节摘要提取 → 合并输出结构化 Markdown + JSON。

资料中的章节类型包括 Research Background、Methodology、Experiment、Dataset、Discussion、Limitations 和 Research Questions。

关键函数：

- `splite_paper_by_title(text)`：按标题拆分论文；
- `classify_section(text)`：分类章节；
- 各类 `extract_*` 函数：提取分段摘要；
- `summarize_paper(text)`：编排流程。

这些函数仅为参考代码，尚未满足当前 ArtifactVersion、Evidence、SourceSnapshot、Prompt registry 和安全边界。

## 3. 可研究的设计问题

资料使用事实一致性和认知覆盖等维度评价摘要，并讨论多评估器和迭代纠正方法。评分公式、模型组合和报告结果均属于第三方研究设计，不能直接成为本项目产品指标。

- PaperSummary 应覆盖哪些字段，如何处理缺失章节；
- finding 与 limitation 如何逐项绑定 Evidence；
- 如何用人工 Benchmark 评估事实一致性；
- 如何衡量内容覆盖而不鼓励模型补写；
- 校验失败时如何标记 unsupported 或创建新的执行记录。

## 4. 不可直接采用的内容

- 不假定更换模型配置即可完成迁移；
- 不将第三方七类章节直接作为当前生产 Schema；
- 不将多模型投票视为事实保证；
- 不为追求字段完整度补写无 Evidence 内容；
- 不将第三方 Benchmark 数字写成星文智析能力指标；

## 5. 采用门禁

参考思想进入实现前，必须在项目论文与推理 Benchmark 上验证 Schema、Evidence、人工正确率和运行成本，并由 Model Policy、Prompt Registry 与 Reasoning Protocol 明确采用范围；不得直接复用第三方 Schema 或指标。
