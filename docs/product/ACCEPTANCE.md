# Acceptance Criteria

## 1. MVP 总验收

| 编号 | 标准 | 必须证明 |
| --- | --- | --- |
| G-01 | 公网 Demo 可访问 | URL、首页截图、主流程截图 |
| G-02 | 主案例完整跑通 | 从输入到导出的连续录屏或截图链 |
| G-03 | 数据来自真实来源 | 来源 URL、查询参数、获取时间 |
| G-04 | 输出可导出 | CSV、数据字典、溯源报告 |
| G-05 | 文献总结结构化 | PaperSummary JSON 和页面展示 |
| G-06 | 图谱可溯源 | 节点/边详情能看到 evidence |
| G-07 | 反馈可修正 | 反馈前后结果差异和修正记录 |
| G-08 | 缓存兜底可用 | 模拟外部失败时仍能演示主案例 |

## 2. A 前端验收

| 项目 | 标准 |
| --- | --- |
| 页面完整性 | 首页、任务流程、数据结果、文献总结、图谱、反馈页面可访问 |
| 状态完整性 | 加载、成功、失败、缓存模式均有明确提示 |
| 数据展示 | 数据表、字段字典、来源、质量评分可读 |
| 图谱交互 | 节点可点击，边或详情面板能展示证据 |
| 展示质量 | 页面适合答辩录屏，不像临时后台页面 |

## 3. B 后端验收

| 项目 | 标准 |
| --- | --- |
| API | `API_CONTRACT.md` 中核心接口可用 |
| 状态机 | 任务状态按 DESIGN 定义流转 |
| Qwen Client | 模型调用集中封装，支持超时和错误处理 |
| 数据库 | 任务、来源、结果、反馈可持久化 |
| 缓存 | 外部服务失败时可返回最近一次真实运行结果 |
| 安全 | API Key 不进前端、不进日志、不进仓库 |

## 4. C 数据验收

| 项目 | 标准 |
| --- | --- |
| 数据源 | 至少 2 类真实来源或 1 个主源 + 1 个可解释补充源 |
| 字段映射 | 关键字段有名称、含义、单位、来源 |
| 清洗 | 缺失值、单位、类型转换规则明确 |
| 质量评分 | 字段覆盖率、缺失率、来源完整性、单位一致性可计算 |
| 导出 | CSV 和字段字典可复现生成 |

## 5. D 文献与图谱验收

| 项目 | 标准 |
| --- | --- |
| 文献总结 | 覆盖研究目标、方法、数据、结论、局限 |
| 来源绑定 | 核心总结绑定 paper/source/evidence |
| 图谱结构 | 节点类型和边类型符合 DATA_MODEL |
| 证据链 | 图谱边必须有 `evidence_ids` |
| 可信性 | 不把无来源模型输出作为事实 |

## 6. 文档验收

| 文档 | 标准 |
| --- | --- |
| README | 能让新成员 5 分钟理解项目、入口、文档地图 |
| PRD | 范围清楚，知道什么做、什么不做 |
| DESIGN | 架构、状态机、模块边界、缓存、安全清楚 |
| API_CONTRACT | 前后端可据此并行开发 |
| DATA_MODEL | 数据、文献、图谱、证据字段一致 |
| ROADMAP/BACKLOG | 能直接拆 Issue 和排优先级 |
| SECURITY/DEPLOYMENT | 密钥、部署和公网 Demo 风险明确 |

## 7. 一票否决项

出现以下情况，MVP 不算完成：

- 公网 Demo 无法访问。
- 前端直接暴露 API Key。
- 数据、文献或图谱结果无法追溯来源。
- 缓存数据是手写假数据且未标注。
- 宣传材料把未实现能力写成已实现。
- API 或数据模型与文档明显不一致。
